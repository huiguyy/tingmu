## 一、对话发生了什么（10-28，事实层）

对话两个角色：**技术开发者**（演示工具方）与**产品经理**（提出产品设想方）。

1. 技术开发者现场演示了一个自己已在用的实时转写工具："你直接说，它直接把所有的文字都生成出来了""我都是这样子"——实时语音转文字能力已被真机验证，**不需要从零造 ASR**（工具未记名）。
2. 产品经理反馈"很接近了""就是再优化一下"，并说出核心场景（大意）：
   > "做个这样的 app 或小程序。我是听障人士，你在这块一说话，我打开它，屏幕上显示的都是大字，立马成字……他这个字还是很小，无非就是把这个界面再优化一下。"
3. 技术开发者补充竞品参照："得到刚出了一个，它能够区分出是谁来……到最后他还立马就能给你总结出来，关了以后。"（未记名；特征=转写+分人+总结，疑 Get 笔记类，待核实。）

## 二、用户拍板了什么（10-29，事实层）

1. **形态=原生 APP，不是小程序**："听障人士确实有做成 APP 的，因为准备直接把模型放在本机上。"
2. **运行要求=端侧整体运行**："要做到在普通手机上端侧整体运行。"（不是旗舰机，普通手机。）
3. **v1 功能范围只做三块**（原话"一开始仅做这么几个功能"）：
   - 交互与显示界面：全屏滚动实时字幕（横竖屏）＋ 左上角说话指示点（如蓝点闪动=有人在说）＋ 触屏浮现右下角设置图标；
   - 设置·模型选择：本地模型 / 云端模型（选云端时要能填云端模型的账号）；
   - 设置·外观：字号；文字颜色与背景颜色（默认白底黑字，可反转黑底白字，可设其他色调）。
4. **参考产品=微信输入法的 AI 录音笔**（截图已归档）。

**一句话产品定义：听幕 = 给听障人士的面对面实时字幕 APP，引擎跑在手机本机（普通手机可整体离线运行），v1 差异点 = 听障向大字界面 + 极简交互。**

## 四、v1 交互与界面规格（权威规格，按用户 10-29 口述整理）

### 4.1 主界面（字幕页）

1. **字幕区**：整个屏幕（横屏或竖屏）滚动显示语音转成的文字，字幕实时不断出现；正在说的话跟随更新、说完定格。〔建议〕定格句不透明、进行中句半透明；保留最近 3 句可回看。
2. **状态提示**：左上角一个简单的点（如蓝色点），**闪动=有人在说话**——由 VAD（语音活动检测）驱动，不做花哨动效。
3. **设置入口**：一碰屏幕，右下角出现"设置"图标。〔建议〕数秒无操作自动隐去，避免误触；从设置返回时录音不中断。
4. 〔建议，借鉴参考截图〕底部细条：录音计时＋停止按钮；主界面强制屏幕常亮（字幕工具熄屏=中断），参考截图底部"请保持屏幕常亮，熄屏可能导致录音中断"的提示文案可借用。

### 4.2 设置页（v1 仅以下两项）

1. **模型选择**：
   - 本地模型（默认）：〔建议〕列出可下载/已下载的端侧模型包，标注体积与实时率；
   - 云端模型：选择厂商＋填写云端模型的账号（AppID/Key 类凭据）＋〔建议〕连通性测试按钮。
2. **外观设置**：
   - 字体大小（〔建议〕4 档起，默认特大）；
   - 文字颜色＋背景颜色：默认白底黑字；可反转黑底白字；可自定义色调。〔建议〕提供几组高对比预设（白/黑/黄字深底等）＋自定义取色。

### 4.3 与参考截图（微信输入法 AI 录音笔）的关系

- 截图要素：居中大块声浪可视化＋"AI 实时总结中…"＋底部计时/波形/红色停止钮＋常亮提示。
- **借鉴**：计时、停止控制、屏幕常亮策略与提示文案。
- **不借鉴**：大占屏的装饰性声浪与云端总结前置——字幕工具的屏幕主体必须是文字本身；总结在听幕属 P2 且默认不放 v1。

## 五、技术方案

### 5.1 端侧引擎（主路，满足 R8）

| 候选 | 特点 | 结论 |
|---|---|---|
| **sherpa-onnx ＋ 流式 Zipformer / 流式 Paraformer（int8）** | 真·流式、中文（有中英双语档）、纯 CPU ARM 可跑、有 Android/iOS 官方示例、Silero-VAD 同库自带 | **主路候选**，P0 实测定档 |
| SenseVoice-Small（非流式） | 中文准确实时率高（约 15× 实时）、带标点，但要按句切（靠 VAD 分段）非逐字流式 | 备选/混用（"说完一句 0.5s 内出"也可接受时） |
| whisper.cpp（tiny/base 量化） | 通用但**非流式**，小模型中文准确率一般，普通手机上勉强 | 不作主路 |

- VAD：Silero-VAD（sherpa-onnx 内置支持）——同时干两件事：驱动左上角说话点（R4）＋ 只把有人说话的音频喂给 ASR（省电省算力）。
- 〔建议〕标点模型（ct-transformer 类）v1 可不上——字幕场景标点不致命，省下的算力给流畅度；P2 做总结时再加。
- **性能预算（P0 在"普通手机"实测定红线）**：实时率 RTF ≤ 0.3；ASR 常驻内存 ≤ 300MB；尾字定格延迟 ≤ 1s；连续 1 小时会话机身可持握不烫手；模型包体积几十~两百 MB 量级（实测后写死）。

### 5.2 云端引擎（设置里的可选项，满足 R6）

- 工程上做**引擎抽象层**：`LocalEngine` / `CloudEngine` 同一接口（麦克风分帧进 → 增量文本出），UI 不感知差异。
- 云端适配器：〔建议〕v1 先接一家（讯飞或阿里实时 ASR），设置页做"厂商＋凭据"的通用填法；后续厂商按同一接口加。

### 5.3 App 工程架构〔建议〕

- **Android 原生（Kotlin）先行**（参考截图为安卓机；APK 可直接分发进听障社群，无商店审核等待）： sherpa-onnx 官方 Kotlin/JNI 示例成熟、长时录音链路最好控。若近期就定 iOS，再评估 Flutter＋sherpa_onnx 插件（代价：多一层插件调试）。
- 长时会话三件事：前台服务（`microphone` 类型）＋ 屏幕常亮 ＋ 麦克风权限引导；**国产 ROM 省电杀后台**要在首启做"电池优化白名单"引导（真实风险，见第七节）。

## 六、开发规划

> 估时口径：单人 + ZCode 结对的业余节奏。

### P0 — 端侧选型实测（第 1 周，2-3 天，**全方案第一块要钉死的石头**）

| 任务 | 内容 | 产出 |
|---|---|---|
| T0.1 端侧跑通 | sherpa-onnx 官方 Android demo ＋ 流式中文模型（Zipformer/Paraformer int8 各一）＋ VAD，装到**普通手机** | 真机演示：离线说话→1s 内上屏 |
| T0.2 性能实测 | 上述预算四项（RTF/内存/延迟/发热）＋模型体积；低配机重点测 | 定档：选哪只模型＋量化档＋红线数字 |
| T0.3 竞品体验 | 微信输入法 AI 录音笔（截图在手，重点体验）、Get 笔记、Google Live Transcribe、音书 App | 一页对比：字号上限/延迟/离线与否/设置项 |
| T0.4 决策回填 | 确认 Android 先行、云端厂商首选 | 回填本文第三节 |

### P1 — APP v1.0（第 2-3 周）＝ R1/R2/R4-R8

- 主界面：全屏滚动字幕（横竖屏）＋ VAD 说话点 ＋ 触屏浮现设置入口 ＋ 计时/停止/常亮。
- 设置页：模型选择（本地默认；云端先接一家＋凭据填写）＋ 外观（字号/文字色/背景色，含高对比预设与自定义）。
- 引擎抽象层 ＋ LocalEngine ＋ CloudEngine。
- 工程：前台服务、权限引导、省电白名单引导。
- 分发：APK 直接给种子用户。
- **验收（全部在普通手机、全程离线测）**：面对面 1 米/3 米、安静/嘈杂；尾字定格 ≤1s；RTF ≤0.3；1 小时会话可持握；**听障目标用户不看口型能复述对方意思**；字号/配色主观满意。

### P2 — 总结与分人（第 4-6 周）＝ R9/R10（均不在 v1）

- **总结（R10）**：待定两条路——端侧小模型（受"普通手机"算力约束，效果存疑）vs 走云端 LLM（选了云端引擎的用户顺手可用；纯本地用户要不要给，P2 再定）。
- **分人（R9）**：端侧说话人日志（sherpa-onnx 有 CAM++ 类说话人嵌入与说话人切换检测示例）先做"按停顿分段＋交替着色"的近似体验；**双机模式**（对方也装、各自转写标"我/对方"）仍是最稳兜底。
- 会话记录：本地保存最近 N 条、可删；默认不自动上传。

### P3 — 打磨与扩大分发（第 7-8 周起）

- iOS 版评估（端侧引擎 sherpa-onnx 支持 iOS，主要是分发/审核成本）。
- 稳定性：弱网只影响云端模式、断句纠错回改、低内存机适配。
- 听障社群种子试用与反馈迭代。

## 七、风险与合规

1. **端侧算力是最大不确定点**：整个方案押在"普通手机 CPU 能实时跑流式 ASR"上——所以 P0 只干这一件事，先钉死再动 UI。
2. **国产 ROM 省电杀后台**：MIUI/EMUI 类系统会掐长时录音；前台服务＋白名单引导是标配，仍要在主流国产机上实测。
3. **发热与续航**：连续麦克风＋推理，预算不达标就降模型档位（int8→更小量化）或 VAD 闲时休眠。
4. **录音合规**：即使端侧、数据不出门，首次启动仍要有清晰的麦克风用途告知；选云端模式时明确"音频会上传到所选厂商"，默认本地。
5. **范围控制**：用户已明确"一开始仅做这么几个功能"——总结/分人/多语言/悬浮窗全部挡在 v1 之外，这是把活干完的前提。

## 八、与现有体系的边界

- 听幕是**全新产品线**，不在《新媒体总纲领 v3》（采集→生产→发布）范围内，不共用多推/content-factory。
